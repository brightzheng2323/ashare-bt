# ashare-bt · A 股日线策略回测框架

一个用来看懂「一个策略在 A 股历史上到底赚不赚钱」的小型回测框架。

**为什么不用现成的库？** 因为 A 股有一堆特殊规则 —— T+1、涨跌停、整手交易、5 元最低佣金，网上的回测示例代码大多不处理，跑出来的收益曲线是假的。这个项目把这些规则做进了引擎本身。

## 安装

需要 [uv](https://docs.astral.sh/uv/)（这台机器上已经有了）：

```bash
uv sync
```

## 跑一个回测

```bash
uv run backtest --code 600519 --start 2020-01-01 --end 2025-01-01 --strategy ma_cross
```

## 常用命令

```bash
uv run backtest list-strategies                 # 看有哪些策略和参数
uv run backtest --code 000001 --strategy rsi --rsi-period 14 --cash 200000
uv run backtest fetch --code 600519             # 只下载数据并缓存
uv run backtest inspect --code 600519           # 数据体检
uv run backtest --code 600519 --json            # 输出 JSON，方便脚本处理
uv run pytest                                   # 跑测试（不联网）
uv run pytest -m network                        # 联网测试（默认跳过）
```

除了直接回测，还有三个子命令：

```bash
uv run backtest explore --code 000001                      # 摊开看：指标 / 筹码 / 各策略此刻的信号
uv run backtest optimize --code 000001 --strategy ma_cross \
    --fast 3,5,10,20 --slow 20,60,120                      # 参数寻优（含过拟合检验）
uv run backtest portfolio --codes 000001,600519,601398 \
    --strategy ma_cross --cash 300000                      # 多股票组合
```

## 内置策略

| 名字 | 思路 | 参数 |
|---|---|---|
| `ma_cross` | 双均线金叉买、死叉卖 | `--fast` `--slow` |
| `macd` | DIF 上穿 DEA 买，下穿卖 | `--fast` `--slow` `--signal` |
| `bollinger` | 跌破下轨买、突破上轨卖 | `--window` `--num-std` |
| `rsi` | RSI 超卖买、超买卖 | `--period` `--buy-below` `--sell-above` |
| `chip_peak` | 获利盘稀少时买、获利盘丰厚时卖 | `--buy-below` `--sell-above` `--max-concentration` `--lookback` |

## 加一个自己的策略

在 `src/ashare_bt/strategies/` 下新建文件：

```python
from ashare_bt.indicators import sma
from ashare_bt.strategies.base import History, Strategy


class MyStrategy(Strategy):
    name = "my_strategy"

    def target(self, h: History) -> float:
        """返回目标仓位：1.0 = 满仓，0.0 = 空仓。

        h 是一个「只能看到今天为止」的视图，
        读明天的数据会直接报错 —— 这是刻意的。
        """
        ma = sma(h.close, 10)
        if ma is None:
            return 0.0
        return 1.0 if h.close[-1] > ma else 0.0
```

然后把它加进 `strategies/__init__.py` 的 `REGISTRY` 就能用 `--strategy my_strategy` 跑。

## 这根框架保证什么

| 保证 | 怎么做到的 |
|---|---|
| 不用当日收盘价成交（未来函数） | T 日收盘出信号，T+1 日开盘成交；信号和成交是主循环里不同迭代的变量 |
| 策略看不到未来数据 | 策略拿到的是 `History` 视图，越界读取直接抛 `LookAheadError` |
| T+1 | 当日买入的股票 `sellable = 0`，次日开盘前才结算为可卖 |
| 涨跌停买不进/卖不出 | 开盘价触及涨跌停价则拒绝，并记录拒绝原因 |
| 佣金最低 5 元 | 按笔计算，小资金回测的关键成本 |
| 指标预热不缺失 | 引擎跑全历史，只在记录时截取回测窗口 |
| 科创板 200 股起、可 1 股递增 | 按板块分别处理整手规则 |
| 涨跌停按**日期**生效 | 创业板 2020-08-24 才改成 20%，主板 ST 2026-07-06 才改成 10% |

## 关于复权：为什么用后复权 + 整体缩放

这是个踩过坑才定下来的设计。

**前复权不能用。** 东方财富的前复权对现金分红用的是减法（`前复权价 = 当时真实价 − 之后累计每股分红`），对分红历史长的股票会把早年价格算成 0 甚至负数：

| 股票 | 非正价 K 线 | 最后一根 |
|---|---|---|
| 平安银行 | 1909 根 | 2009-01-19 |
| 工商银行 | 420 根 | 2014-05-28（之后"价格" 0.04 元） |
| 中国石化 | 95 根 | 2006-11-14 |

0.04 元的股价不是"失真"，是**没有意义**。

**后复权是乘法，永远为正、全历史有效、收益率正确。** 但它把绝对价位放大了（平安银行后复权价 1345 元，真实约 11 元），而价位决定了「10 万本金能买几手」—— 整手取整和 5 元最低佣金都按成交金额起作用，价位错了这两件事就全错。

**所以：** 用后复权，再整体除以一个常数，让**回测起点**的价格等于那天的真实成交价。常数缩放不改变任何收益率，只把价位搬回真实量级。缩放需要真实价格，所以会额外拉一次不复权数据（走缓存，很便宜）。

已知的取舍：只有回测起点附近的价格是真实的，更早的历史价格会被同比例压得偏小（回测窗口内的价格是对的，不影响结果）。用 `--no-rescale` 可以关掉缩放。

## 参数寻优：用来打脸的，不是用来找圣杯的

`backtest optimize` 把回测区间切成两段：**前 70% 找参数，后 30% 检验**。

结果通常是这样的（真跑出来的）：

```
 参数                   样本内收益    样本外收益       衰减
 fast=10 slow=120       +53.05%      -5.35%    -58.40%   ← 样本内冠军
 fast=20 slow=120       +51.41%      -5.79%    -57.20%
 ...
 fast=3 slow=120        +34.11%      +8.02%    -26.09%   ← 样本外冠军

 样本内冠军 fast=10 slow=120
   样本内 +53.05%   样本外 -5.35%   → 它在样本外排第 7 / 11
 全部参数平均            样本内 +19.29%   样本外 -3.83%
 样本外为正的比例  36%
```

**样本内最好的参数，样本外掉到中下游** —— 这不是运气差，这是常态。
你在历史上挑出表现最好的那一组，很大程度上挑的是"这段历史里恰好合适的噪音"。

真正该看的不是"哪组参数收益最高"，而是：
- 全部参数的平均表现如何（说明策略本身有没有边际）
- 参数在样本外为正的比例（说明稳不稳定）
- 样本内差一点点、样本外好得多的那些（那才可能不是噪音）

## 多股票组合：简单但要说清楚局限

`backtest portfolio` 把本金拆成 N 份，每只股票**独立跑一遍**，最后把权益相加。

**局限：子账户之间不会再平衡。** A 股票赚了钱不会挪给 B 用，B 亏光了 A 也不会来救。

**好处：其余一切都是对的。** T+1、涨跌停、整手、5 元最低佣金，每只股票都按真实规则单独结算，不因为套了"组合"的壳就放松；而且完全复用单股引擎，不存在两套逻辑对不上的风险。

注意本金被拆小之后，**5 元最低佣金的影响会放大**。组合跑出来的收益率天然低于逐只单独跑 —— 这不是 bug，是小账户的真实处境。

### 直接用指数成分股

```bash
uv run backtest portfolio --index 000300 --strategy ma_cross --cash 3000000
uv run backtest portfolio --index 000300 --limit 20        # 先拿 20 只试跑
uv run backtest portfolio --index 000016                   # 上证50
uv run backtest portfolio --index 000905                   # 中证500
```

### ⚠️ 前视偏差：用今天的成分股回测过去

**这是这类回测最大的坑，必须知道。**

`--index` 拿到的是**今天**的成分股名单。而沪深300每半年调整一次，今天还留在指数里的股票，本身就是"过去这些年表现没掉队"的那一批 —— 等于提前知道了答案。

实测效果很明显：取当前沪深300名单的前 8 只跑双均线，2020–2025 收益 **+76%**，而同期沪深300指数本身是 **-5%**。差的这 80 个百分点里，很大一部分不是策略的功劳，是名单的功劳。

要做严谨的历史回测，需要**逐个调仓日的成分股名单**，这个接口给不了。所以 `--index` 跑出来的数字应当**偏乐观**看待 —— 报告里也会把这条警告打出来。

### 组合回测会自动对比「等权买入持有」

单个股票可以用「沪深300」当基准，但**组合不行**：指数是市值加权，组合是等权；更要命的是，如果成分股名单本身带着"今天的幸存者"偏差，指数里根本没有这个偏差 —— 拿指数做基准会把选股偏差的功劳错记在策略头上。

所以组合回测会额外算一条**同一批股票的等权买入持有**，并排显示。实测跑出来的结果很能说明问题：

```
 对比
   策略(ma_cross)     累计  +32.25%   年化  +5.99%   回撤  -10.42%   夏普  0.65
   等权买入持有        累计  +82.14%   年化 +13.29%   回撤  -27.84%   夏普  0.73
   沪深300            累计   -5.23%   年化  -1.11%   回撤  -45.60%   夏普  0.04
```

**看第一条和第三条，双均线好像大胜指数 37 个百分点；但看第二条就明白了 —— 它比"什么都不做、平均买下这 300 只股票"少了 50 个百分点，连夏普都没跑赢。**

那 37 个百分点不是策略赚来的，是「用今天的成分股名单回测过去」这个偏差送来的。这就是为什么必须有一条公平的基准。

（双均线也不是一无是处：它把回撤从 -27.84% 压到了 -10.42%。趋势类策略的典型特征就是牺牲收益换低波动 —— 但在这段行情里，牺牲得比换回来的多。）

### 本金门槛

等权持有 300 只股票，本金被拆成 300 份。**买不起一手的股票会全程闲置**，钱就一直趴着。

一手 = 100 股。哪怕平均股价只有 30 元，买一手也要 3000 元，300 只就是 **90 万**才刚够每只买一手。想真正复刻指数，本金需求比直觉高得多 —— 报告里会统计有多少只因为资金不足而全程没交易。

## 关于筹码分布

`chips.py` 用「三角形分布 + 换手衰减」推算持仓成本结构，A 股特有的分析方法。它**不是**交易所公布的数据，是推算出来的。

- 每天把成交量按三角形铺在当天 [最低价, 最高价] 上，峰在平均价
- 旧筹码按当天换手率等比衰减
- 读出：获利盘比例、平均成本、90% 成本区间、集中度

两个已知近似：

1. 平均价用 `(最高+最低+收盘)/3` 而不是真实 VWAP。VWAP 要拿 `成交额/成交量` 算，那是**不复权**口径，和复权后的价格序列混用会算出一个根本不在当日区间里的值。
2. 只回看最近 `lookback` 根（默认 500 根）。不设上限的话分布要覆盖几十年的价格区间，网格被拉宽、近期筹码反而分不清；而且按 0.5% 日换手，500 天前的筹码只剩 8%，本来就没必要算。

## 数据来源

东方财富公开接口，无需 token，一次请求取全部历史。数据缓存到 `data/cache/`，默认一天内不重复下载。

## 已知不做（这一版）

部分仓位（策略只能全仓/空仓）、组合内的动态再平衡、日内数据、ETF/可转债、融资融券、机器学习因子。

## 免责

这是个**教学和分析工具**。回测跑出来的数字不构成任何投资建议 —— 而且历史回测表现对未来收益几乎没有预测力。
